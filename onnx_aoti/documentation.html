onnx_aoti

onnx_aoti turns an ONNX model into an AOTInductor package (.pt2) and runs it natively. Python compiles the model once. After that, Rust and Kotlin load the package through libtorch's AOTInductor runtime, with no Python involved. Kotlin callers can pass an .onnx file directly; the compiled package is cached by content hash.

How it works

model.onnx ──(Python, once)──▶ model.pt2 ──(Rust, libtorch C ABI)──▶ inference
                                   ▲
                 SHA-256 cache key keeps the compiled file for each
                 ONNX file + input shape + dtype + compiler sources
  • Python (onnx_aoti.py): ONNX to PyTorch, torch.export, and aoti_compile_and_package. Adds model_meta.json with the input and output shapes.
  • Rust (rust/): reads the .pt2 zip, extracts the compiled .so, and calls the AOTInductor container API. Exposed as a C ABI (cdylib).
  • Kotlin (kotlin/): calls the C ABI through the Foreign Function & Memory API (JDK 22+). Provides tensors, sessions, and the cache.

1. Compile ONNX to .pt2

From the command line

# Input shape is needed when the ONNX file has dynamic dimensions
env/bin/python onnx_aoti/onnx_aoti.py \
    --input model/model_fp16_clean.onnx \
    --output model/model_compiled.pt2 \
    --input-shape 1,3,224,224 \
    --dtype float32
FlagMeaning
--inputONNX file (required with --output)
--outputOutput .pt2 path
--input-shapeComma-separated static shape. Optional if the ONNX file has static dimensions. Dynamic dimensions default to 1.
--dtypefloat32 (default), float16, or bfloat16

With no flags, the script compiles model/model_fp16_clean.onnx to model/model_compiled.pt2.

What the compile does to the graph

  1. FP16 to FP32 (--dtype float32). The source model stores weights and some casts in FP16. Converting only the PyTorch module is not enough: in-graph Cast nodes to FLOAT16, FP16 initializers, FP16 Constant nodes, and FP16 value types are rewritten to FLOAT32. Without this, tracing fails with Input type (c10::Half) and bias type (float) should be the same.
  2. Static shape and constant folding. When an input shape is given, the ONNX input dimensions are pinned to it and onnxslim folds constants. Shape-driven ops (Shape → Gather → Reshape) become constants. The 512×512 version of model_fp16_clean.onnx folds from 5,366 nodes to 1,469 in about 8 s. Without folding, the export fails with GuardOnDataDependentSymNode on the reshape inside the graph.
  3. Conversion. The folded graph is converted with convert_checked, exported with torch.export, and compiled with AOTInductor.

The compiled package is valid only for the shape it was compiled with. To run a different height and width, compile again with that shape.

Checking the compiled package against ONNX Runtime

tests/parity_check.py runs the original ONNX file in ONNX Runtime and the compiled package on the same random input in [0, 1). It reports max and mean absolute differences, then checks every element against |pt2 - ort| ≤ atol + rtol · |ort|. 

env/bin/python onnx_aoti/tests/parity_check.py \
    --onnx model/model_fp16_clean.onnx \
    --pt2 model/model_compiled_512.pt2 \
    --shape 1,3,512,512 \
    --atol 1e-2 --rtol 1e-2

The script compares element by element with |pt2 - ort| ≤ atol + rtol · |ort|, like np.allclose. It prints max and mean absolute differences before the verdict, and the number of elements that fall outside the tolerance.

The source model is FP16 and the compiled model is FP32, so some difference is expected. Use the measured max and mean differences to decide whether the tolerance is appropriate.

From Python

import torch
from onnx_aoti import compile_onnx_to_pt2

compile_onnx_to_pt2(
    "model/model_fp16_clean.onnx",
    "model/model_compiled.pt2",
    input_shape=[1, 3, 224, 224],
    dtype=torch.float32,
)

The function converts the model with convert_checked, exports it with torch.export, and compiles it with aoti_compile_and_package. It then appends model_meta.json to the zip. The Rust and Kotlin loaders read that file, so they need no shape arguments.

2. Run a .pt2 from Python

import torch
from onnx_aoti import AOTIModule

model = AOTIModule("model/model_compiled.pt2")
out = model(torch.randn(1, 3, 224, 224))   # must match the compiled input shape

3. Operator coverage and checked conversion

onnx_op_handler.convert_checked(onnx_model) is the conversion entry point used by compile_onnx_to_pt2:

  • Preflight. Custom ONNX domains are errors. Data-dependent ops (NonZero, NonMaxSuppression, Unique, Loop, If, Scan) and dynamic input dimensions are warnings. ONNX checker failures are warnings.
  • Constant folding. Constant shape, axes, and index inputs are baked into the module, so torch.export sees static values. This covers Reshape, Slice, Squeeze, Unsqueeze, the Reduce* family, TopK, CumSum, Expand, Pad, ConstantOfShape, Resize, and OneHot.
  • Error reporting. Every failing node is collected, and one ONNXConversionError lists them all.

Register your own converter for an op:

from onnx_op_handler import register_converter

def my_converter(node, consts, opset):
    # return fn(*inputs) to handle the node, or None to fall back to onnx2pytorch
    return lambda x, *_: x * 2

register_converter("MyOp", my_converter)

The op sweep (tests/test_op_coverage.py) checks 87 single-node ops against onnxruntime. All 87 pass. Ops whose output shape depends on runtime values still fail under AOTInductor.

4. Rust library

The crate in rust/ builds libaoti_ffi.dylib (macOS) or libaoti_ffi.so (Linux) for the C ABI, plus an rlib for Rust callers. 

use aoti_ffi::AotiModel;

let model = AotiModel::load("model/model_compiled.pt2", 1)?;  // 1 = concurrent instances
let outputs = model.run(&input, &[1, 3, 224, 224])?;          // Vec<Tensor>, copies
model.run_into(&input, &shape, &mut out_buf)?;               // writes into your buffer
let view = model.run_view(&input, &shape)?;                  // borrows libtorch memory

Run the Rust example:

cd onnx_aoti/rust
LIBTORCH=/path/to/torch cargo run --release --example infer -- ../tests/artifacts/small_net.pt2

5. Kotlin/JVM API

All types are in the default package of kotlin/aoti-demo.jar.

Type or memberPurpose
AotiLibrary.default()Loads the native library bundled in the jar. Override with -Daoti.ffi.lib=... or AOTI_FFI_LIB.
AotiLibrary.load(path, numRunners = 1)Loads a .pt2 file and reads its shapes. The path can be absolute, relative to the working directory, or absolute to a parent of it.
AotiLibrary.loadOnnx(onnxPath, inputShape, dtype, numRunners, cacheDir, pythonBin, compilerScript)Loads an ONNX file through the cache. Compiles it on a cache miss. See the cache section.
AotiDtypeFLOAT32, FLOAT16, BFLOAT16
Model.inputShape, outputShapeShapes from model_meta.json (LongArray).
Model.inputNumel, outputNumelElement counts.
Model.allocateInput(), allocateOutput()New zeroed FloatTensor with the model's shape.
Model.predict(input)Runs the model and returns a new FloatTensor. One copy of the output.
Model.newSession()Returns an InferenceSession with pre-allocated input and output.
FloatTensorNative float32 tensor that owns its memory. Members: shape, numel, copyFrom(FloatArray), toFloatArray(), get(i), set(i, v), close(). Factories: FloatTensor.zeros(vararg shape), FloatTensor.of(data, vararg shape).
InferenceSessioninput, output (both FloatTensor), run(), close(). Closing a session does not close the model.
AotiExceptionThrown for load, run, and compile errors. Compile errors include the Python output.

Concurrency and lifetime

  • Model.predict and session run() can be called from several threads at once. numRunners sets how many can run in parallel. Use one InferenceSession per thread. A single model without a session is safe to call from many threads if you tolerate allocation, which each call pays for.
  • Model.close() waits for calls in progress to finish. Calls after close() throw IllegalStateException.
  • FloatTensor uses a shared arena, so it can be passed between threads. A tensor must be closed once. Using it after close() throws IllegalStateException.

6. Kotlin examples

Each example assumes lib is an AotiLibrary and model is a Model. The imports are java.nio.file.Path and the classes above.

6.1 Load from an ONNX file

import java.nio.file.Path

val lib = AotiLibrary.default()

// First call compiles the ONNX file with Python and caches the result.
// Later calls, including in new processes, load the cached .pt2 directly.
lib.loadOnnx(
    onnxPath = Path.of("model/model_fp16_clean.onnx"),
    inputShape = longArrayOf(1, 3, 224, 224),   // required when the ONNX input has dynamic dimensions
    dtype = AotiDtype.FLOAT32,
    numRunners = 4,
).use { model ->
    println("input=${model.inputShape.toList()} output=${model.outputShape.toList()}")
}

6.2 Load a compiled .pt2 directly

lib.load(Path.of("model/model_compiled.pt2"), numRunners = 2).use { model ->
    println("expects ${model.inputNumel} input values")
}

6.3 One call with predict

lib.loadOnnx(Path.of("tests/artifacts/small_net.onnx")).use { model ->
    val data = FloatArray(model.inputNumel.toInt()) { i -> kotlin.math.sin(i * 0.01).toFloat() }

    FloatTensor.of(data, *model.inputShape).use { input ->
        model.predict(input).use { output ->
            println("shape=${output.shape.toList()} values=${output.toFloatArray().toList()}")
        }
    }
}

predict checks that the input shape matches the model. It allocates the output and copies it once.

6.4 Hot loop with a session

lib.loadOnnx(Path.of("model/model_fp16_clean.onnx"), inputShape = longArrayOf(1, 3, 224, 224)).use { model ->
    val frame = FloatArray(model.inputNumel.toInt()) { 0.1f }

    model.newSession().use { session ->
        session.input.copyFrom(frame)        // reuse the same input buffer
        repeat(1000) {
            session.run()                    // writes into session.output, no allocation
        }
        println("first values: ${session.output.toFloatArray().take(5)}")
    }
}

6.5 Several threads

import kotlin.concurrent.thread

lib.loadOnnx(Path.of("tests/artifacts/small_net.onnx"), numRunners = 4).use { model ->
    val workers = (1..4).map { id ->
        thread {
            model.newSession().use { session ->       // one session per thread
                session.input.copyFrom(FloatArray(model.inputNumel.toInt()) { id * 0.1f })
                repeat(200) { session.run() }
            }
        }
    }
    workers.forEach { it.join() }
}

6.6 Write your own inputs and read outputs

lib.load(Path.of("model/model_compiled.pt2")).use { model ->
    model.allocateInput().use { input ->
        input[0L] = 0.5f                      // element access by flat index
        input[1L] = -0.25f
        model.predict(input).use { out ->
            val first = out[0L]
            println("first output value: $first")
        }
    }
}

6.7 Handle errors

try {
    lib.loadOnnx(Path.of("bad.onnx"))
} catch (e: AotiException) {
    // Compile errors include the Python traceback
    println(e.message)
}

try {
    FloatTensor.zeros(2, 2).use { it.copyFrom(FloatArray(3)) }   // wrong size
} catch (e: IllegalArgumentException) {
    println(e.message)
}

The 512×512 export fails. After folding, the graph has 21 Shape ops and 2 Cast nodes, so the static folding is not complete. torch.export raises a data-dependent guard on a Resize. The compiler output is in /tmp/compile512.log and /tmp/x.pt2.log.

Measuring predict()

Main.kt now prints the average time of model.predict(input).close() over 500 calls after 20 warm-up calls. It uses the static zero-copy path, so it includes one output copy and one allocation. To measure only inference, reuse a session.

DraftExport or TORCH_LOGS=dynamic can help identify which nodes stay dynamic. Or set resize_resolved_sizes in the ONNX model with the target sizes.

predict allocates the output and copies it once. session.run() writes into the pre-allocated output, so it is faster. The warm load includes first-call JVM and FFM setup, which is why it is larger than the predict time.

7. The .pt2 cache

loadOnnx keys the cache by a SHA-256 hash of:

  • the .onnx file bytes, plus the .onnx.data external-weights file if present
  • the input shape (auto if none is given)
  • the dtype
  • the Python compiler sources (*.py next to the compiler script)

Cache file: <cacheDir>/<hash>.pt2. The defaults are:

SettingDefaultEnvironment variable
Cache directory~/.cache/onnx_aotiAOTI_CACHE_DIR
Pythonenv/bin/python, searched upward from the working directory, else python3AOTI_PYTHON
Compiler scriptonnx_aoti/onnx_aoti.py, searched upwardAOTI_COMPILER_SCRIPT

Hashing a large file is slow, so the content hash is stored in <cacheDir>/index.tsv, keyed by canonical path, file size, and modification time (for the .onnx file and its .onnx.data companion if present). When those match, the file is not read again. On the 145 MB model_fp16_clean.onnx, the first hash takes about 190 ms and an index hit about 1.4 ms.

  • Cache hit: Python is not started. The package loads directly.
  • Cache miss: Python compiles the file into a temp file, then renames it into the cache. A compile takes several seconds (about 8 s for the test model). Concurrent callers wait for the same compile.
  • Errors: a failed compile raises AotiException with the Python traceback. The compile times out after 30 minutes.

Pre-warm the cache in CI and ship the .pt2 files with your application, so production machines don't need Python unless they see a new model.

Limitations

  • Only single-output models are supported in Rust and Kotlin.
  • Compiled packages are static-shape. Dynamic dimensions default to 1 unless you pass a shape.
  • The Rust library depends on libtorch's internal C ABI (AOTInductorModelContainer*, aoti_torch_*). Recheck it after each PyTorch upgrade.
  • The PyTorch and onnxslim versions are not part of the cache key. Clear the cache directory after upgrading either.
  • A compiled package is specialized to its input shape. Changing height or width needs a new compile, which is a separate cache entry.
  • The index trusts size and modification time. A file rewritten with the same size and an unchanged modification time (for example cp -p of different content) keeps its old hash. Delete index.tsv to force a rehash.
  • A warm load of the small test model takes 220–460 ms on this machine, including first-call JVM and FFM setup.
  • predict copies the output once. run_into and sessions avoid that copy.
  • The bundled library links libtorch by absolute path. Distributing it needs libtorch bundled too, and the jar only contains the platform that built it (macos-aarch64 here).
  • Ops that produce output shapes from runtime values (NonZero, Unique, NonMaxSuppression, Loop, If) are not supported.
  • float16 and bfloat16 compilation are not tested.
  • Error paths for wrong buffer sizes, non-float32 outputs, and multi-output models are not tested.
